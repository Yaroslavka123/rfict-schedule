# План ручной проверки расписания 2026

Цель: проверить полный путь от создания трёх Google Sheets таблиц для 1/2/3 курса до редактирования занятий, delayed autosave, JSON в GitHub и webhook.

## 0. Предусловия

- В репозитории удалены старые файлы `public/schedule/course_1/*.json`, `course_2/*.json`, `course_3/*.json`, если нужна чистая проверка.
- В каждой тестовой таблице стоит актуальная версия Apps Script из `apps_script/labs_form/`.
- В Apps Script включён timezone `Europe/Minsk` в `appsscript.json`.
- В Script Properties заданы:
  - `GITHUB_TOKEN` с доступом `Contents: Read and write` к репозиторию.
  - `WEBHOOK_URL`, если проверяется backend webhook.
- Для замера задержки подготовлена таблица/заметка с колонками: курс, лист, ячейка, время правки, время появления commit/json, фактическая задержка.

## 1. Создание трёх таблиц

Повторить для курсов 1, 2, 3.

1. Открыть ссылку эталонной Google-таблицы с окончанием `/copy`.
2. Создать копию с понятным названием, например:
   - `РФиКТ расписание 2026 курс 1`
   - `РФиКТ расписание 2026 курс 2`
   - `РФиКТ расписание 2026 курс 3`
3. Обновить страницу и убедиться, что появилось меню `Расписание`.
4. Открыть `Расписание → Первоначальная настройка`.
5. При необходимости вставить код публикации.
6. Нажать `Настроить таблицу` и выдать разрешения.
7. Проверить в мастере: шаблон готов, триггер готов, автосохранение выключено.

## 2. Настройка курса и генерация листов на 2026

Повторить для каждой таблицы.

1. Открыть генератор семестра.
2. Заполнить параметры:
   - Учебный год: `2025`, если генерируется весенний семестр 2026 учебного года `2025-2026`.
   - Семестр в году: `2` для весны 2026.
   - Курс: текущий курс таблицы.
   - Даты и длительность семестра — по вашему учебному календарю.
3. Нажать `Сгенерировать`.
4. Проверить шапки на каждом листе:
   - `A2` = номер курса.
   - `D1` содержит правильный глобальный семестр и учебный год `2025-2026`.
   - `D3` содержит `Курс N  Очная форма получения образования`.
5. Проверить даты в колонке A:
   - `08.02.2026` не должен быть понедельником.
   - Неделя `09.02-14.02` должна начинаться с `Пн 09.02`.
   - Для нескольких листов сверить дни недели с внешним календарём.
   - Все даты записаны без года в формате `DD.MM`.
6. Проверить звонки:
   - обычные перерывы равны значению из формы;
   - большой перерыв стоит после 5-й пары.
7. Проверить, что шаблон не съехал:
   - координаты шапки те же;
   - группы в строке 5;
   - дни в колонке A;
   - пары в колонке B;
   - время в колонке C;
   - ячейки занятий и аудиторий остались попарными.

## 2.1. Копирование расписания с прошлой недели

1. Заполнить неделю 1 несколькими разными занятиями:
   - обычное занятие;
   - занятие с цветным фоном;
   - объединённую лабораторную на несколько пар;
   - аудитории.
2. Открыть лист недели 2.
3. Нажать `Расписание → 📋 Копировать с прошлой недели`.
4. Проверить текст подтверждения и согласиться.
5. Убедиться, что на неделе 2:
   - перенесены занятия, аудитории, RichText, цвета и объединения;
   - не изменились даты, номера пар, звонки и шапка;
   - размеры строк и колонок не изменились.
6. Изменить расположение групп на неделе 2 и повторить проверку:
   - операция должна остановиться с понятной ошибкой.

## 3. Настройка автосохранения

Повторить для каждой таблицы.

1. Открыть `Расписание → 🌐 Автосохранение на сайт`.
2. Включить автосохранение.
3. Подтвердить диалог.
4. Проверить, что в `A2` листов указан правильный курс.
5. В Document Properties убедиться, что `PUSH_ENABLED=true`.
6. В Triggers убедиться, что нет старых зависших `runDelayedExport_` триггеров до начала замера.

## 4. Первичный ручной экспорт

Повторить для каждой таблицы.

1. Нажать `Расписание → 💾 Сохранить расписание сейчас`.
2. Подтвердить диалог.
3. Проверить Apps Script Executions:
   - нет ошибок `GITHUB_TOKEN not set`;
   - нет ошибок GitHub API 403/409;
   - если задан webhook, нет ошибок `webhook error`.
4. Проверить GitHub:
   - курс 1 пишет в `public/schedule/course_1/`;
   - курс 2 пишет в `public/schedule/course_2/`;
   - курс 3 пишет в `public/schedule/course_3/`.
5. Для каждого курса открыть несколько файлов `1.json`, середину семестра и последний файл.
6. Проверить корневые поля JSON:
   - `course` соответствует таблице;
   - `semester` соответствует глобальному семестру;
   - `week_number` соответствует названию листа;
   - `date_range` соответствует названию листа;
   - `groups` заполнены;
   - `lessons` не пустой, если на листе есть занятия.
7. Проверить каждое занятие:
   - есть поле `date`;
   - формат `YYYY-MM-DD`, например `2026-02-09`;
   - `date` соответствует `day` и `day_number`;
   - для занятий одного дня дата одинаковая;
   - при переходе на следующий день дата увеличивается на 1.

## 5. Проверка delayed autosave и debounce

Проводить минимум на одном листе каждого курса.

1. Выбрать одну ячейку занятия на листе недели.
2. Зафиксировать время T0 с точностью до секунд.
3. Изменить занятие через sidebar или вручную в ячейке.
4. Сразу открыть Apps Script Triggers и проверить, что появился один `runDelayedExport_` trigger.
5. Через 60 секунд внести вторую правку на том же листе.
6. Проверить, что старый trigger заменён новым, а не накопилось несколько одинаковых триггеров.
7. Больше не редактировать таблицу.
8. Через 2 минуты после последней правки проверить:
   - trigger исчез;
   - появился commit/обновление файла в GitHub;
   - обновился только JSON этого листа, если правился один лист.
9. Замерить фактическую задержку:
   - ожидаемо около `2 минут + время выполнения экспорта`;
   - допустимо несколько дополнительных секунд на Apps Script/GitHub.
10. Повторить с правками на двух разных листах в течение одной debounce-паузы:
    - ожидаемый результат: `_pendingExportSheet=__ALL__`, экспортируются все листы таблицы.

## 6. Проверка редактирования через форму

На каждом курсе проверить минимум один обычный урок и одну лабораторную/мульти-запись.

1. Открыть sidebar.
2. Выбрать обычное занятие:
   - тип;
   - предмет;
   - преподаватель;
   - аудитория;
   - подгруппа/чётность;
   - комментарий;
   - при необходимости `ОТМЕНА`.
3. Нажать `Применить`.
4. Проверить ячейку:
   - предмет жирный;
   - подгруппа/комментарий красные;
   - отмена жирная красная;
   - аудитория в соседней правой ячейке;
   - цвет фона соответствует типу.
5. Дождаться autosave и проверить JSON:
   - `subject`, `teacher`, `room`, `subgroup`, `frequency`, `comment`, `cancelled` соответствуют форме;
   - `date` остался датой дня строки.
6. Проверить лабораторную/мульти-запись:
   - несколько блоков подгрупп разделяются строкой-разделителем;
   - аудитории разделяются синхронно;
   - JSON содержит отдельные записи для каждого блока;
   - у всех записей есть правильная `date`.

## 7. Проверка ручного редактирования ячеек

1. Вручную изменить текст занятия в ячейке.
2. Вручную изменить аудиторию в соседней правой ячейке.
3. Дождаться autosave.
4. Проверить JSON:
   - парсер не потерял предмет;
   - аудитория обновилась;
   - тип занятия сохранился по цвету фона;
   - `date` не изменилась ошибочно.
5. Очистить занятие и аудиторию.
6. Дождаться autosave.
7. Проверить, что запись исчезла из `lessons` соответствующего JSON.

## 8. Проверка webhook

Если `WEBHOOK_URL` задан.

1. После ручного экспорта и после autosave проверить логи backend.
2. Для каждого события проверить payload:
   - `event=schedule_updated`;
   - `file` указывает на правильный `course_N/week.json`;
   - `course`, `semester`, `week_number`, `date_range`, `lessons_count` корректны.
3. Проверить, что backend смог скачать raw JSON из GitHub.
4. Проверить, что backend видит новое поле `lessons[].date`.

## 9. Проверка удаления старых JSON

1. До чистого экспорта удалить старые JSON в нужных папках.
2. После экспорта убедиться, что созданы только актуальные недели.
3. Проверить, что нет файлов не от того курса, например таблица курса 1 не пишет в `course_3`.
4. Если был ошибочный экспорт, удалить ошибочные файлы и повторить после проверки курса в `A2`.

## 10. Контрольные значения для 2026

Использовать как быстрые проверки календаря:

| Дата | День недели |
|------|-------------|
| 08.02.2026 | Вс |
| 09.02.2026 | Пн |
| 14.02.2026 | Сб |
| 16.02.2026 | Пн |
| 01.09.2026 | Вт |
| 07.09.2026 | Пн |

## 11. Что считать успешным результатом

- Все 3 таблицы имеют правильный курс и генерируют недели 2026 без сдвига календаря.
- JSON каждого курса появляется только в своей папке `course_1`, `course_2`, `course_3`.
- В каждом объекте `lessons[]` есть поле `date`.
- `date` в формате `YYYY-MM-DD` и соответствует строке дня.
- Autosave срабатывает после 2 минут тишины, а частые правки сбрасывают таймер.
- При правках одного листа экспортируется один лист; при правках нескольких листов за debounce — все листы.
- Webhook получает корректные payload и backend может скачать обновлённый JSON.
- Нет накопления лишних time-based triggers.

## 12. Откат и диагностика

- Если JSON ушёл не в тот курс: выключить автосохранение, проверить курс в `A2`, удалить ошибочные JSON, включить снова.
- Если autosave не срабатывает: проверить `PUSH_ENABLED`, installable trigger `onSheetEdit`, Apps Script Executions и наличие `GITHUB_TOKEN`.
- Если GitHub API возвращает `403`: проверить права токена.
- Если GitHub API возвращает `409`: повторить ручной экспорт после паузы.
- Если webhook падает: временно убрать `WEBHOOK_URL` или чинить backend отдельно; GitHub export должен продолжать работать.
- Если даты в колонке A неверные: остановить экспорт, проверить год/семестр генератора и timezone проекта.
