## Обзор

Workflow пользователя:

1. Кликает на ячейку в таблице расписания
2. Открывает **«Расписание → ➕ Добавить / редактировать занятие»**
3. Выбирает тип занятия (Лекция / ЛБ / ПЗ / Семинар / Куратор), опционально ДО
4. Заполняет поля: предмет, подгруппа, преподаватель, аудитория, даты, комментарий
5. Нажимает **«Применить» (Ctrl+Enter)** — ячейка заполняется правильным форматом:
   - Правильный цвет фона по типу
   - Название предмета жирным шрифтом
   - Подгруппа, даты, комментарий красным
   - Аудитория в соседней колонке справа

Если ячейка уже заполнена → форма открывается **с её данными** для редактирования.

## Установка

**Требования:** доступ редактора к Google Spreadsheet с расписанием.

### Шаг 1: Скопировать код

1. Открой таблицу расписания → **Расширения → Apps Script**
2. В файле `Код.gs` (`Code.gs`) удали всё → вставь содержимое [`Code.gs`](./Code.gs)
3. Нажми **«+» → HTML** рядом с «Файлы» → назови `Sidebar` (без `.html`) → вставь [`Sidebar.html`](./Sidebar.html)
4. В **⚙ Project Settings** → включи **Show "appsscript.json"** → замени на [`appsscript.json`](./appsscript.json)
5. Сохрани (Ctrl+S)

### Шаг 2: Настроить Script Properties

В Apps Script: **⚙ Project Settings → Script Properties → Add**:

| Key | Value | Обязательно |
|-----|-------|:-----------:|
| `GITHUB_TOKEN` | [Fine-grained PAT](https://github.com/settings/personal-access-tokens/new) с правами `Contents: Read and write` на `Yaroslavka123/rfict-schedule` | ✓ |
| `WEBHOOK_URL` | URL Go backend endpoint (POST). Получает уведомления об обновлениях | — |

### Шаг 3: Настроить триггер

В Apps Script: **Triggers** (часы слева) → **Add Trigger**:
- Function: `onSheetEdit`
- Event source: From spreadsheet
- Event type: On edit

### Шаг 4: Разрешения

1. Обнови страницу таблицы (Ctrl+R / F5) → появится меню **«Расписание»**
2. При первом запуске Google попросит разрешения:
   - Нажми **«Дополнительно»** → **«Перейти к проекту (небезопасно)»** → **«Разрешить»**
3. Нажми **«Расписание → 🔄 Пересоздать справочник из таблицы»** для инициализации словарей

Готово!

### 4 курса

Каждый курс — **отдельная Google таблица** со своим Apps Script. Номер курса определяется в два этапа:

1. **Явный override** через меню «🎓 Курс: …» — сохраняется в `DocumentProperties` и имеет приоритет.
2. **Fallback на ячейку A2** (формат `N курс`) — используется, если override не задан.

JSON пушится в: `public/schedule/course_{N}/`

Для нового курса: скопируй Apps Script + настрой `GITHUB_TOKEN` в новой таблице + укажи номер курса через «🎓 Курс: …».

## Курс и Push-режим

Чтобы случайно не перезаписать чужой курс из новой/чужой таблицы, экспорт в GitHub защищён двумя слоями.

### Курс (явный override)

- Пункт меню **«🎓 Курс: N»** (или **«🎓 Курс: не указан»**) — клик открывает prompt, где надо ввести число 1–8.
- Значение хранится в `PropertiesService.getDocumentProperties()` (ключ `COURSE_OVERRIDE`) — привязано к конкретной таблице.
- Пустой ответ в prompt — сброс. Тогда курс будет браться из ячейки **A2** (как раньше).
- При включении Push override **обязателен** — без него тумблер не включается.

### Push в GitHub (тумблер)

- Пункт меню **«🚀 Push в GitHub: ВКЛ/ВЫКЛ»** — глобальный тумблер автоэкспорта.
- Хранится в `PropertiesService.getDocumentProperties()` (ключ `PUSH_ENABLED`).
- **По умолчанию ВЫКЛ** (тестовый режим). Это значит:
  - `onSheetEdit` не планирует debounce-экспорт.
  - `applyLesson` (sidebar → «Применить») заполняет ячейку, но **не пушит**.
  - `⚡ Обновить расписание сейчас` показывает alert «Push выключен».
- При включении показывается **confirm-диалог** с курсом, репозиторием и каталогом назначения.
- При выключении — confirm «Выключить Push?».
- При попытке включить без указанного курса — alert «Сначала укажи курс».

### Тестовый прогон

Пункт меню **«🧪 Тестовый прогон (parse без push)»**:

- Работает на **активном листе недели** (имя должно содержать `…(N-я неделя)`).
- Вызывает `parseWeekSheet_()` и показывает summary:
  - effective курс (с пометкой `override` или `из A2`)
  - кол-во групп
  - кол-во занятий
  - разбивка по типам
- **JSON в GitHub не уходит** — это просто превью того, что напарсится.
- Доступен и при ВКЛ, и при ВЫКЛ Push — для быстрой проверки парсинга после правок.

### Сценарий «новая таблица»

Когда копируешь скрипт в свежую таблицу нового курса:

1. `Push в GitHub` уже ВЫКЛ (default) — можно спокойно редактировать.
2. Заполняй ячейки через sidebar, прогоняй «🧪 Тестовый прогон» чтобы убедиться, что всё корректно парсится.
3. Установи `GITHUB_TOKEN` в Script Properties.
4. Открой «🎓 Курс: …» → введи номер.
5. Открой «🚀 Push в GitHub: ВЫКЛ» → подтверди включение.
6. С этого момента любая правка через 2 мин уходит в `public/schedule/course_{N}/`.

## ДО-модификатор

ДО (дистанционное обучение) — это **не отдельный тип**, а надстройка. Чекбокс «ДО (дистанционное)» появляется после выбора любого типа.

Комбинации:
- Лекция + ДО = дистанционная лекция (цвет лекции)
- Лаба + ДО = дистанционная лаба (цвет лабы, 2 пары)
- Практика + ДО = дистанционная практика
- и т.д.

При включении ДО сохраняется цвет и логика основного типа.

## Подгруппы и мульти-блок

### Обычное занятие (не лаба)

Одна секция с полями:
- Предмет, преподаватель, аудитория
- Чекбоксы подгрупп: 1ПГ, 2ПГ, 3ПГ, 4ПГ, 5ПГ, 6ПГ
- Выбор: каждую неделю / нечётные / чётные
- Кнопка **«+ ещё предмет»** переключает в мульти-режим

### Лаба / мульти-блок

Каждая подгруппа — отдельный блок с заголовком **«Подгруппа #N»**:

| Поле | Описание |
|------|----------|
| Предмет | Autocomplete (может отличаться по подгруппам) |
| Подгруппа | Чекбоксы 1ПГ–6ПГ |
| Чёт/нечёт | Частота занятий |
| Преподаватель | Autocomplete |
| Аудитория | Autocomplete |
| Период | с ДД.ММ по ДД.ММ |
| Комментарий | Свободный текст |
| ОТМЕНА | Чекбокс отмены для этой подгруппы |

Блоки подгрупп визуально выделены:
- Рамка (`border`) с закруглением и тенью
- Крупный заголовок (16px, bold)
- Контрастный фон

Кнопка **«+ ещё предмет/подгруппа»** добавляет новый блок. Максимум ограничен только шириной ячейки.

### Как данные записываются

**Мульти-блок** (лаба с подгруппами):
- Ячейка объединяется по вертикали (merge) на `spanRows` строк
- Все подгруппы пишутся в одну ячейку через разделитель `───────────────`
- Аудитории пишутся в соседнюю ячейку справа через разделитель `───`
- И ячейка, и аудитория объединены (merge) одинаково

**Одно занятие:**
- Пишется в одну ячейку (без merge)
- Аудитория в соседней ячейке справа

## Структура ячейки

### Ячейка занятия (lesson cell)

Пример содержимого (многострочный текст в одной ячейке):

```
с 03.03 по 26.05          ← красный, даты периода
БИС                       ← жирный чёрный, предмет
1ПГ/2ПГ нечет/чет          ← красный, подгруппа
ст.пр. ПопкоЕ.Е.          ← обычный чёрный, преподаватель
608 на 15.05               ← красный, комментарий
ОТМЕНА                     ← жирный красный (если отменено)
```

### Ячейка аудитории (room cell)

Рядом справа. Для мульти-блока:

```
708
───
К1
```

Шрифт: Arial 12pt, жирный, по центру.

### Цвет фона

Обе ячейки (lesson + room) имеют одинаковый цвет фона, определяемый типом занятия.

## RichText формат

Ячейки используют RichText (стилизованный текст) вместо plain text. Это позволяет парсеру (`parseRichLessonCell_`) точно разбирать содержимое по стилям, без эвристик.

### Правила стилизации

| Стиль | Позиция в ячейке | Поле в JSON |
|-------|------------------|-------------|
| Красный (`#ff0000`) | До предмета | `period_start`, `period_end` |
| **Жирный чёрный** | Первая значимая строка | `subject` |
| Красный | После предмета, до преподавателя | `subgroup`, `frequency` |
| Обычный чёрный | После предмета | `teacher` |
| Красный | После преподавателя | `comment` |
| **Жирный красный** | Любая позиция, текст `ОТМЕНА` | `cancelled: true` |

### Как это работает

1. **Запись** (`buildCellContent_` + `applyRichTextToCell_`):
   - Строит текст из массива подгрупп
   - Создаёт массив `styleRanges` с позициями и стилями
   - Применяет RichTextValue через `SpreadsheetApp.newRichTextValue()`

2. **Чтение** (`parseRichLessonCell_` + `buildStyleMap_`):
   - Получает RichText runs из ячейки
   - Строит карту `charIndex → {bold, red}` из runs
   - Для каждой строки определяет стиль первого символа
   - По стилю решает, куда положить строку (subject, teacher, subgroup, comment)

Шрифт всех стилей: **Arial 12pt**.

## Справочники

### Хранение

Словари хранятся в скрытом листе **«Справочники»** (создаётся автоматически):

| Столбец A (Предметы) | Столбец B (Преподаватели) | Столбец C (Аудитории) |
|---|---|---|
| БИС | ст.пр. ПопкоЕ.Е. | 708 |
| ИАД | доц. ИвановИ.И. | К1 |
| ... | ... | ... |

### Инициализация

Меню **«Расписание → 🔄 Пересоздать справочник из таблицы»**:
- Сканирует все листы книги
- Извлекает предметы (по жирному шрифту), преподавателей (по префиксам `доц./ст.пр./асс.`), аудитории (по числовому формату)
- Сохраняет в лист «Справочники»

### Автодополнение

При применении занятия через форму:
- Новые предметы / преподаватели / аудитории автоматически добавляются в справочник
- Кэш словарей: **60 секунд** (`CacheService.getScriptCache()`)

### Ручное редактирование

Меню **«Расписание → 📋 Открыть справочник»** — откроет лист, можно править руками.

## Автоэкспорт и debounce

### Механизм

```
Изменение ячейки
    ↓
onSheetEdit / applyLesson
    ↓
scheduleDelayedExport_(sheetName)
    ↓  (удаляет предыдущий таймер, создаёт новый)
┌──────────────────────────────────────┐
│  time-based trigger (2 мин)          │
│  Каждое новое изменение → сброс      │
└──────────────┬───────────────────────┘
               ↓  (2 мин тишины)
    runDelayedExport_()
        ↓
    dispatchScheduleUpdate_()
        ↓
    ┌───────────┬───────────┐
    ↓                       ↓
pushFileToGitHub_()    notifyWebhook_()
```

### Константы

| Константа | Значение | Описание |
|-----------|----------|----------|
| `EXPORT_DELAY_MS` | `2 * 60 * 1000` | Задержка debounce (2 минуты) |
| `GH_REPO_OWNER` | `Yaroslavka123` | Владелец репозитория |
| `GH_REPO_NAME` | `rfict-schedule` | Имя репозитория |
| `SCHEDULE_DIR` | `public/schedule/` | Директория JSON файлов |

### Источники экспорта

| Источник | Когда | Debounce | Требует Push: ВКЛ |
|----------|-------|:--------:|:-----------------:|
| `onSheetEdit` | Любая ручная правка ячейки (кроме листа «Справочники») | ✓ | ✓ |
| `applyLesson` | Нажатие «Применить» в sidebar | ✓ | ✓ |
| `manualDispatch` | Меню «⚡ Обновить расписание сейчас» | — | ✓ (+ confirm) |
| `testParseRun` | Меню «🧪 Тестовый прогон» | — | — (никогда не пушит) |

> При `PUSH_ENABLED=false` все debounce-экспорты тихо подавляются. Сидбар продолжает работать (заполнение ячеек идёт штатно), но JSON не отправляется.

### Обработка нескольких листов

Если за время debounce изменились **разные листы** → `_pendingExportSheet` устанавливается в `__ALL__` → экспортируются все листы.

Если один лист → экспортируется только он (быстрее).

### Важно: openById

`runDelayedExport_()` вызывается из time-based триггера, где `getActiveSpreadsheet()` возвращает `null`. Поэтому при планировании сохраняется ID таблицы (`_pendingExportSpreadsheetId`), и при выполнении используется `openById()`.

## Webhook для Go backend

После каждого успешного пуша в GitHub, Apps Script отправляет POST на `WEBHOOK_URL` (если задан в Script Properties):

```json
{
  "event": "schedule_updated",
  "file": "public/schedule/course_3/14.json",
  "course": 3,
  "semester": 6,
  "week_number": 14,
  "date_range": "11.05-16.05",
  "name": "11.05-16.05(14-я неделя)",
  "generated_at": "2026-05-13T23:03:57.271Z",
  "lessons_count": 260
}
```

Ошибки webhook логируются в `console.warn`, но не прерывают экспорт.

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Меню «Расписание» не появилось | Открой Apps Script → запусти `onOpen` вручную |
| Sidebar без кнопок | Файл должен называться **`Sidebar`** (без `.html`, регистрозависимо) |
| Форма не сохраняет | Убедись, что ячейка выбрана (подсвечена) в Google Sheets |
| `GitHub API: 409` | Конфликт SHA. Нажми «⚡ Обновить расписание сейчас» ещё раз |
| `GitHub API: 403` | Токен без прав. Пересоздай PAT с `Contents: Read and write` |
| Расписание не обновляется | Проверь: 1) `GITHUB_TOKEN`, 2) триггер `onSheetEdit`, 3) Executions |
| Отложенный экспорт не срабатывает | Удали мёртвые триггеры в Triggers, проверь Executions |
| Скрипт просит разрешения | «Дополнительно» → «Перейти к проекту (небезопасно)» → «Разрешить» |
| Словари пустые | Нажми «🔄 Пересоздать справочник из таблицы» |
| Хочу удалить скрипт | Apps Script → правый клик на `Code.gs` → «Удалить». Данные останутся |
