## Фаза 0 — Исправление критических багов

**Цель:** стабильная работа текущего функционала перед добавлением нового.

### B1 — Селект курса/группы не показывает выбранное значение

**Файл:** `src/components/layout/TopFilters.svelte:76,87`

**Проблема:** `value={filters.course}` / `value={filters.group}` не синхронизируется с визуальным отображением после закрытия выпадающего списка. Svelte 5 реактивность не триггерит обновление `selectedIndex`.

**Решение:**
```svelte
<!-- Заменить value={...} на bind:value -->
<select bind:value={filters.course} ...>
```
или явно задавать `selected` через итерацию опций.

**Проверка:** выбрать курс → закрыть селект → открыть снова → выбранное значение отображается.

---

### B2 — Селект недели пустой

**Файл:** `src/App.svelte:75-83`, `src/components/layout/TopFilters.svelte:99-108`

**Проблема:** `filters.week = 1` по умолчанию, но неделя 1 может отсутствовать. `<select value="1">` не находит `<option value="1">` → браузер показывает пустой селект.

**Решение:**
```typescript
// App.svelte — $effect при загрузке schedule
$effect(() => {
  if (!schedule) return
  const availableWeeks = Array.from(new Set(schedule.weeks.map(w => w.week_number))).sort()
  if (availableWeeks.length > 0 && !availableWeeks.includes(filters.week)) {
    filters = { ...filters, week: availableWeeks[0] }
    return
  }
  // существующая логика findCurrentWeek
})
```

**Проверка:** открыть курс, где нет недели 1 → селект показывает первую доступную неделю.

### B3 — План-факт: предметы не отображаются

**Файл:** `src/features/analytics/AnalyticsView.svelte`

**Проблема:** `buildSubjectsByCourse()` содержит баг: `return selectedCourse !== 'all'` как fallback для уроков без course_number. При `selectedCourse = 'all'` все такие уроки исключаются.

**Решение:** заменить `return selectedCourse !== 'all'` на корректный fallback по курсу.

**Проверка:** выбрать «Все курсы» → план-факт показывает предметы для всех курсов.

---

### B4 — Ошибка сохранения плана

**Файл:** `src/features/analytics/AnalyticsView.svelte:133-149`

**Проблема:** при ошибке PUT запроса происходит тихий rollback без уведомления.

**Решение:** уже реализовано — `catch` показывает `alert()`. Проверить что бэкенд принимает `PUT /api/v1/plan`.

**Проверка:** изменить план → нажать Save → при ошибке появляется alert.

### B5 — Дубли триггеров в Apps Script

**Файл:** `apps_script/labs_form/Code.gs:1084-1097`

**Проблема:** `ensureSingleEditTrigger_()` не защищает от создания второго триггера другим пользователем.

**Решение:**
1. Хранить ID триггера в `ScriptProperties`
2. В `onOpen` чистить мёртвые триггеры
3. При включении автосохранения удалять все существующие триггеры `onSheetEdit` перед созданием нового

**Проверка:** 2 пользователя включают автосохранение → в списке триггеров ровно 1 запись.

## Фаза 1 — Apps Script: установка и новый функционал

**Цель:** упростить установку для не-программиста, добавить кнопку копирования предметов, исправить генератор семестра.

### 1.1 — Упрощение установки

**Цель:** человек без опыта программирования устанавливает скрипт за <5 минут.

**Выбранный вариант: копия эталонной Google-таблицы**
- Администратор поддерживает одну эталонную таблицу с привязанным актуальным Apps Script
- Пользователь открывает ссылку с окончанием `/copy` и создаёт копию
- Меню «🚀 Первоначальная настройка» проверяет шаблон, сохраняет код публикации и создаёт триггер
- Автосохранение остаётся выключенным до проверки сгенерированных листов

**Файлы:**
- `apps_script/labs_form/SetupDialog.html` — мастер первого запуска
- `apps_script/labs_form/INSTALLATION.md` — инструкция для пользователя и администратора
- `apps_script/labs_form/Code.gs` — функции статуса и настройки

**Статус:** реализовано в коде, нужна ручная проверка на копии эталонной таблицы.

### 1.2 — Кнопка «Копировать предметы из прошлой недели»

**Логика:**
1. Определить текущий лист (активная неделя)
2. Найти лист прошлой недели (`week_number - 1`)
3. Проверить совпадение строк пар и расположения групп
4. Скопировать содержимое, RichText, цвета и объединения колонок групп из прошлой недели на текущую
5. НЕ трогать колонки A (день), B (пара), C (время), шапку, размеры строк и колонок
6. Перед заменой показать подтверждение, особенно если активный лист уже заполнен

**Файл:** `apps_script/labs_form/Code.gs` — новая функция `copyFromPreviousWeek()`

**UI:** новый пункт меню «📋 Копировать с прошлой недели»

**Статус:** реализовано в коде, нужна ручная проверка на реальных листах.

### 1.3 — Генератор пустого семестра: правки

**Файл:** `apps_script/labs_form/Generator.gs`, `apps_script/labs_form/GeneratorDialog.html`

**Изменения:**

1. **Большой перерыв после 5-й пары**
   - В `computeBellSchedule_()` всегда использовать `lunch_min` после 5-й пары
   - Не показывать пользователю лишние поля выбора второй смены

2. **Дата всегда без года**
   - Генератор всегда пишет `DD.MM`
   - Поле выбора формата даты в диалоге не показывается

3. **Дефолты как в текущем расписании**
   - `first_start: '08:30'`
   - `pair_min: 90`
   - `break_min: 10`
   - `lunch_min: 40`
   - `num_pairs: 8`

**Статус:** реализовано в коде, нужна ручная проверка генерации полного семестра.

## Фаза 3 — Сайт: План-факт (редактор)

**Цель:** полноценное редактирование плана с формой-редактором, оверрайдами на группу и batch-сохранением.

### 3.1 — Модель данных

**Файл:** `src/types/schedule.ts`, `src/api/scheduleClient.ts`

**CoursePlanEntry** расширяется полем `group?: string`:
```typescript
interface CoursePlanEntry {
  course: number
  subject: string
  lesson_type?: LessonType
  planned_pairs: number
  group?: string              // undefined = уровень курса, строка = оверрайд группы
}
```

**planKey()** учитывает group:
```
"математика::lecture"           — уровень курса
"математика::lecture::ИКБО-01"  — оверрайд конкретной группы
```

**PUT /api/v1/plan** — тот же эндпоинт, но в JSON добавляется `group`. Бэкенд либо игнорирует (не ломается), либо сохраняет.

### 3.2 — Form-Editor: отдельный компонент

**Новый файл:** `src/features/analytics/PlanFormEditor.svelte`

**Структура:**
```
PlanFormEditor
├── Заголовок: курс, сводка (план / расп. / пров.)
├── Список предметов (scroll)
│   └── Для каждого предмета:
│       ├── Название, тип (бейдж)
│       ├── Поле ввода [число] — план на курс
│       ├── Кнопка «➕ Для группы»
│       │   └── Если раскрыто: поля для каждой группы курса
│       │       ├── [число] — оверрайд
│       │       └── ✕ — удалить оверрайд
│       └── Строка статистики: расп. N / пров. N
└── Footer: [Сохранить все изменения] + счётчик изменений
```

**Логика:**
- Собирает все уникальные `{ subject, type }` из lessons выбранного курса(ов)
- Группирует по `course → subject → type`
- Для каждого `(subject, type)` — одно главное поле (уровень курса)
- При нажатии «➕ Для группы» — показывает поля для всех групп этого курса
- Оверрайды визуально выделены (курсив, другой фон)
- Счётчик: «Изменено: 3» в футере

### 3.3 — View/Edit toggle в AnalyticsView

**Файл:** `src/features/analytics/AnalyticsView.svelte`

- Две кнопки в шапке: «📊 Просмотр» / «✏️ Редактор»
- **Просмотр** — текущая read-only таблица (buildPlanFactHierarchy, progress bars, CSV)
- **Редактор** — split layout: PlanFormEditor слева (40%) + таблица справа (60%, read-only, синхронизирована)
- Состояние `mode: 'view' | 'edit'`

### 3.4 — Batch сохранение

**Файл:** `AnalyticsView.svelte`, `scheduleStore.ts`

- **batchUpdatePlan(entries: CoursePlanEntry[]): Promise<{ ok: number; errors: CoursePlanEntry[] }>**
- `Promise.allSettled` — не ломает весь batch из-за одной ошибки
- Оптимистичное обновление: все entry сразу применяются к плану
- При ошибке — rollback только тех, что не сохранились
- UI: «Сохранено 5, ошибок 1. Попробовать снова?»

### 3.5 — CSV экспорт

- Остаётся в режиме просмотра
- Автоматически учитывает оверрайды (через visibleRows)

### Тесты Фазы 3

- [ ] Режимы просмотра и редактора переключаются без потери данных
- [ ] Поле ввода на уровне курса сохраняется

## Фаза 4 — SSE: реалтайм обновления

**Цель:** при изменении расписания в Google Sheets данные на сайте обновляются без кнопки «Обновить».

### 4.1 — Изучить SSE эндпоинт бэкенда

**Действие:** запросить у backend-команды документацию `GET /api/v1/schedule/events`.
Понять:
- Формат событий (`schedule_updated`, `lesson_changed`)
- Какие поля приходят (course, week_number, version)
- Heartbeat интервал

### 4.2 — Подключить EventSource в scheduleStore

**Файл:** `src/stores/scheduleStore.ts`

```typescript
function subscribeToSSE(course: number) {
  eventSource?.close()
  eventSource = new EventSource(`${API_BASE_URL}/api/v1/schedule/events?course=${course}`)
  eventSource.addEventListener('schedule_updated', (event) => {
    const data = JSON.parse(event.data)
    if (data.course === currentCourse) {
      void fetch(currentCourse, true) // force refetch
    }
  })
}
```

### 4.3 — Fallback polling

Если SSE недоступен:
- Polling `GET /api/v1/schedule/updates?course=N` раз в 10 секунд
- Сравнивать `version` — если изменился → refetch

### Тесты Фазы 4

- [ ] При изменении ячейки в Google Sheets → данные на сайте обновляются < 5 сек
- [ ] При обрыве соединения — автоматическое переподключение
- [ ] Fallback polling работает если SSE недоступен
